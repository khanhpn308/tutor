# Recovery procedure

During normal execution or after automatic context compaction, keep the same AGY session and continue from disk without asking the operator. Only if the process/session is actually lost, the operator can restore it using the documented agy --continue or /resume, or select coursera-producer in a new session and give the exact course/batch ID. There is no automatic cross-session relaunch in Harness. Run `course_harness/.venv/bin/python -m course_harness.native_tools resume --course COURSE --batch BATCH`. Read disk state rather than relying on earlier conversation memory.

For a pending lesson, prepare it. For a recorded Worker/Repair output, continue visual processing without generating content again. For a recorded Auditor response, validate it without calling Auditor again. For a validated audit, continue publication. A verified PASS is skipped. HUMAN_ACCEPTED legacy lessons are never changed or copied over. Failed diagnostics are preserved; nonfatal terminal lessons do not prevent the next eligible lesson.

If prepare-lesson returns recover_existing_native_invocation, inspect its saved packet and output slots, then recover the SAME running/completed native subagent via the AGY runtime. Record an existing successful result before continuing. Do not launch another AI call merely because the parent session was interrupted. If the original invocation cannot be recovered, record an explicit transient failure, retaining evidence, before preparing a replacement. Never overwrite output slots from an earlier attempt.

Use `record-failure --course COURSE --batch BATCH --lesson LESSON --category transient --diagnostic '...'` only for an actual infrastructure failure. There are at most 3 failed dispatches per lesson. This does not increment educational repair count. Use categories lesson, integrity, authentication or budget as appropriate. Integrity/authentication/budget halt the batch. A terminal nonfatal quality failure remains available for human diagnosis and the next lesson continues.

Malformed audit JSON, a wrong candidate hash or changed source/asset evidence is not an educational FAIL. Preserve the original evidence and report the error. Do not reset state to force PASS, edit checkpoint hashes or silently re-ingest a changed source. Changes to agent/tool/specification contracts require explicit review before reusing a batch. This migration has a one-time reviewed upgrade snapshot pinned by SHA-256: upgrade-continuous accepts only that exact original state, revalidates all sources/artifacts, archives the old batch/checkpoints and changes scheduling metadata. M01-L01/M01-L02 PASS checkpoint bytes remain unchanged. Their old contract is accepted only while their bytes match the pinned snapshot. In-progress work acquires the new policy binding on its next normal save. Other contract changes are still fatal.

Continuous mode never stops because 30 minutes elapsed or five lessons finished. report-batch returns advance-batch when eligible work remains in the saved scope; invoke it automatically. It preserves the previous report and selects the next group. resume follows successor links, including a crash after the successor file was saved but before its link/pointer was updated. Never restart failed terminal lessons or widen an explicitly selected scope.

AGY automatically compacts older conversation turns; allow this and reread the skill and disk checkpoint afterward. When an AGY /goal is active, use its native continuation across turns. Do not end a goal at a batch boundary. The operator may start it once with /goal followed by the course request; this is not a per-lesson or per-batch prompt handoff. Do not fake slash commands through a shell, create an external loop to restart AGY, or claim automatic transfer into a new session.

If the runtime really cannot continue, first preserve any available in-flight output. Use `PY suspend --course COURSE --batch BATCH --category runtime --diagnostic 'actual runtime/quota failure'`. This sets PAUSED without failing a lesson, clearing an active invocation or losing successful work. Do not repeatedly issue resume while quota remains unavailable. A supported runtime continuation or an operator restoring service can call resume; it reactivates the same checkpoint. For explicit user cancellation use category cancelled, which records CANCELLED; automated resume never reopens it. Integrity/authentication/budget-critical failures remain HALTED and are never auto-reopened. Existing in-flight returns may still be recorded after a stop, but no new invocation is prepared.

Only explicit bounded mode keeps the historical 30-minute/call/known-token bounds. Missing usage remains NOT_VERIFIED, with no invented monetary accounting.
