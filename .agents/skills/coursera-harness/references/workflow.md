# Native production workflow

Run commands from the repository root. In the commands below, `PY` denotes `course_harness/.venv/bin/python -m course_harness.native_tools`, not a shell variable that must be installed. Pass real IDs from JSON outputs; do not type literal placeholders.

1. Run `PY preflight --course Agile_Project_Management`. Confirm source/baseline integrity. This command does not establish runtime model access or native invocation success.
2. Run `PY list-lessons --course Agile_Project_Management`. Read source types/status and skip HUMAN_ACCEPTED, verified native PASS, LOCKED and UNAVAILABLE lessons. Ask only for a genuinely ambiguous course selection. Exact lesson IDs in the user request take precedence.
3. Inspect generated_course/COURSE/native_v2/active_batch.json. If present, run `PY resume --course COURSE --batch BATCH` before starting anything new. Otherwise run `PY start-batch --course Agile_Project_Management --mode continuous --limit 5`. Default scope is the whole manifest. If the user supplies exact lesson IDs, pass ALL of them with --lessons; --limit controls group size, not total scope. Persist the returned batch ID and scope. Use --mode bounded only when explicitly asked to process a single group and stop. Only one active batch per course is allowed. The reviewed pre-continuous batch can be upgraded using upgrade-continuous; never reset it or silently replace its policy hash.
4. For the next lesson, run `PY prepare-lesson --course COURSE --batch BATCH --lesson LESSON`. This persists a unique attempt before any AI invocation and returns a packet path, required custom-agent name and output paths.
5. For `invoke_native_subagent`, invoke the named custom AGY subagent using the actual native `invoke_subagent` tool, in shared workspace storage and a NEW context. Pass the packet path, not the Producer conversation. Wait using the runtime's own supported lifecycle controls. If the tool is absent, stop with NATIVE_DELEGATION_UNAVAILABLE. Do not emulate it with a command, default agent, role prompt or existing session.
6. Worker/Repair writes Markdown to the packet output path. Auditor has only `view_file` and returns strict audit JSON; Producer saves those returned JSON bytes to the packet output path without changing verdicts, hashes, findings or scores. Save the original native tool result as JSON to runtime_evidence_output_path. Metadata unavailable in the actual return must stay unavailable; see the evidence contract.
7. Run `PY record-attempt --course COURSE --batch BATCH --lesson LESSON --attempt ATTEMPT --artifact OUTPUT_PATH --runtime-evidence RUNTIME_RETURN_PATH`. This archives original bytes and persists the next action. Never manually edit state or hand off prompts to the operator.
8. For `process-visuals`, run `PY process-visuals --course COURSE --batch BATCH --lesson LESSON`. This renders Mermaid, normalizes links by figure ID using the authoritative manifest, freezes a new final candidate and validates structure, asset safety and source constraints. BLOCKED stops this lesson. No Auditor or publication may advance while structural/visual errors remain. Keep render failures as diagnostics; do not mark them as educational audit FAILs.
9. For `auditor`, call prepare-lesson and invoke a NEW coursera-auditor. Its packet includes source, candidate SHA, manifest SHA and draft validation, without Worker reasoning or prior verdict. Do not pass the entire checkpoint to Auditor. After record-attempt, run `PY validate-audit --course COURSE --batch BATCH --lesson LESSON`. JSON Schema, Rubric 2.0, figure count and exact hashes are independently checked. The tools never overwrite an Auditor's claimed hash to manufacture a match.
10. For `repair`, call prepare-lesson and invoke a NEW coursera-repair with verified findings. Record its result, process visuals again, prepare a NEW Auditor, record and validate that audit. Maximum 2 educational repair results. INCONCLUSIVE or a missing independent context routes to human review. Invalid audit schema/hash is a diagnostic/integrity failure, not an educational repair request.
11. For `publish`, run `PY publish --course COURSE --batch BATCH --lesson LESSON`. It rechecks all gates and copies the exact audited candidate and assets to a new publication directory. It does not touch v1 modules. Human visual review remains pending; no automatic HUMAN_ACCEPTED.
12. Run `PY report-batch --course COURSE --batch BATCH` after each lesson and group. For next_action prepare-lesson, continue next_lesson. For next_action advance-batch, run `PY advance-batch --course COURSE --batch BATCH`, adopt its returned batch_id, and continue step 4 immediately. This operation stores the completed report and links the successor atomically per file, recovering partial updates idempotently. Do not yield, request approval or ask for Continue at the boundary. For next_action done with a completed scope, report publications and all failures. COMPLETED_WITH_FAILURES means eligible work was exhausted, not that failed lessons passed. For next_action stop, report the actual halt/suspension reason. Resume follows saved successor links and never repeats a verified PASS.

Continuous mode has no 30-minute, 40-dispatch or 500,000-token hard stop. Those historical bounds apply only to explicitly bounded mode. Actual native quota/runtime limits and tool permissions still apply. Tokens omitted by AGY remain unreported. Monetary cost is separate and NOT_VERIFIED. The tools never call providers or retry AI requests. Producer may retry actual transient native failures up to 3 failed dispatches per lesson, using fresh prepared attempts, with at most 2 educational repairs. After that record BLOCKED with diagnostics and continue other lessons. Unrecoverable integrity/authentication/native capability failures halt safely. See recovery-procedure.md for actual runtime exhaustion or cancellation.

AGY documents /goal for native continuation across turns and automatic context compaction. Keep an existing goal active until the assigned scope is exhausted, not merely one group. A plain course request also defaults to continuous scheduling in Producer; /goal adds AGY's runtime stop guard when the operator uses it at startup. Neither custom frontmatter nor Python activates a hidden goal setting. Do not invent native session-handoff tools or claim process restart is automatic.
